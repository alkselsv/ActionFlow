# Domain docs

This project uses a single-context layout:
- GLOSSARY.md at the repository root defines domain vocabulary.
- docs/adr/ holds architecture decision records.

Before exploring, read the glossary and ADRs relevant to the task.
If they do not exist, proceed silently. Domain-modeling creates them
as terms and decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses and tests.
Note vocabulary gaps for domain-modeling.
Surface conflicts with existing ADRs explicitly.
