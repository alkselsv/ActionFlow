# Скиллы Matt Pocock: краткая инструкция для ActionFlow

В проекте установлены скиллы из [mattpocock/skills](https://github.com/mattpocock/skills). Этот справочник помогает выбрать процесс; точные инструкции находятся в `.agents/skills/<name>/SKILL.md`.

## Как вызывать

В Codex напиши имя скилла с `$` и задачу:

```text
$research Изучи обработку редакций сообщений в Cognee и сохрани выводы в docs/research/.
```

Скилл также можно выбрать в интерфейсе. Скиллы с `disable-model-invocation: true`, включая `to-spec`, `to-tickets` и `implement`, вызываются явно.

## Процесс для ActionFlow

```text
Нерешённые вопросы → $grill-with-docs
Согласованные требования → спецификация
Спецификация + дорожная карта → $to-tickets
Готовый GitHub Issue → новая сессия с $implement
Реализация → $tdd по применимости → $code-review
```

Спецификация первого эксперимента уже есть: [responseflow-mvp.md](../specs/responseflow-mvp.md). Работы и зависимости описаны в [ROADMAP.md](../ROADMAP.md). Повторная публикация всей спецификации для начала декомпозиции не требуется.

Пример следующего шага:

```text
$to-tickets Подготовь задачи M0 из docs/ROADMAP.md с учётом
docs/specs/responseflow-mvp.md. Сохрани связь с AF-ID, зависимости
и критерии приёмки. Выдели открытые решения и задачи для человека.
Покажи декомпозицию перед публикацией в GitHub.
```

`to-tickets` предлагает проверяемые вертикальные задачи. Заготовки дорожной карты можно объединять или делить; связь с AF-ID сохраняется. Подготовительные исследования и согласование правил должны иметь собственный проверяемый результат. Готовность к реализации определяется разрешёнными вопросами и выполненными зависимостями.

Для готового тикета используй фактический номер GitHub Issue:

```text
$implement Реализуй GitHub issue #<номер>. Учитывай связанный AF-ID,
спецификацию MVP и критерии приёмки тикета.
```

## Дополнительные ситуации

- `$triage` — разобрать неподготовленное обращение или bug report в GitHub. Готовые задачи из `to-tickets` не требуют повторного triage.
- `$handoff` — подготовить передачу контекста в новую сессию.
- `$pr` — написать описание pull request.
- `$writing-for-agents` — обновить AGENTS.md или инструкции для агентов.
- `$setup-matt-pocock-skills` — перенастроить трекер и документы скиллов; текущая настройка уже выполнена.

Остальные установленные скиллы выбираются по их `SKILL.md`; полный каталог для первого эксперимента не нужен.

## Что учитывать

- `to-spec` публикует спецификацию в настроенный трекер; `to-tickets` публикует согласованные задачи. Здесь используется GitHub `alkselsv/ActionFlow`; перед публикацией проверяется доступ через `gh` и целевой репозиторий.
- `implement` включает проверки, code review и коммит в текущую ветку. Особые ограничения задачи указывай при вызове.
- Направление работы задают [AGENTS.md](../../AGENTS.md), спецификация и дорожная карта. Исследование или одноразовый прототип сами по себе не включают новую возможность в MVP.
- Используй [GLOSSARY.md](../../GLOSSARY.md), [правила трекера](issue-tracker.md), [метки](triage-labels.md) и [правила доменных документов](domain.md). При изменении требований согласованно обновляй документы и связанные тикеты.
