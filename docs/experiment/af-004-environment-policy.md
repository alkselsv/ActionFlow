# AF-004: условия работы с данными и контур эксперимента

Дата: 2026-11-20. Статус: утверждено владельцем проекта при закрытии [issue #2](https://github.com/alkselsv/ActionFlow/issues/2). Связанные документы: [AF-001: исходные данные](af-001-source-data.md), [спецификация](../specs/responseflow-mvp.md), [дорожная карта](../ROADMAP.md). Версии и проверка совместимости: [af-004-stack.md](af-004-stack.md).

## Решение

Первый этап выполняется локально и только на синтетических данных. Внешние LLM/embedding-провайдеры разрешены при явной настройке провайдера, модели и ключей; секреты хранятся вне Git. По решению владельца от 2026-11-24 для подключения выбран VseLLM с моделью `openai/gpt-5.5`; интеграция не означает допуска модели по качеству — сравнение и оценка остаются в AF-023/AF-025. Без заполненных ключа и модели используется локальный baseline. Платные вызовы допускаются только при заданном `ACTIONFLOW_LLM_BUDGET_USD`; до появления автоматического контроля суммарного бюджета также установите лимит расходов в кабинете VseLLM.

## Контур и доступ

- Разработка и проверка — на одной машине через Docker Compose.
- Приложение слушает localhost и не публикуется в интернете. Внешний хостинг, staging-контур и домен не используются.
- Единственный менеджер входит с той же машины. Многопользовательский доступ и удалённый вход не входят в этот этап.
- Живой пилот с реальными пользователями не разворачивается. Его размещение выбирается отдельно, если понадобится.
- Прикладная БД и хранилища Temporal — локальные контейнеры с отдельными базами и пользователями; конкретная схема выбирается в [#4](https://github.com/alkselsv/ActionFlow/issues/4).

## Данные

- Используются только синтетические fixtures из `data/fixtures/telegram/`.
- Реальные переписки Vedita отсутствуют и не загружаются.
- Если реальные данные появятся позже: хранить их вне Git в согласованной закрытой папке, ограничить доступ, не создавать копии и резервные копии до отдельного согласования, удалить после завершения эксперимента, обезличить перед любой публикацией.
- Вложения и голосовые не анализируются; их наличие может учитываться как ограничение полноты данных по спецификации.

## Секреты

- Секреты не попадают в Git, fixtures, GitHub Issues, документацию и логи.
- Хранение: хранилище секретов ОС или локальный `.env`, исключённый `.gitignore`. В репозитории допустим только `.env.example` с именами переменных без значений.
- Учётные данные LLM/embedding-провайдера создаются только владельцем проекта и передаются приложению через `.env` или хранилище секретов ОС.
- Перед коммитом проверяется, что env-файлы и ключи не попали в `git status`, а приложение не печатает секреты в логах.

## Хранение, удаление, резервные копии

- Синтетические fixtures версионируются в Git и хранятся бессрочно.
- Реальные данные не используются, поэтому срок хранения и резервное копирование для них сейчас не применяются.
- Резервное копирование БД и восстановление для пилота определены в [#19](https://github.com/alkselsv/ActionFlow/issues/19) и [runbook AF-021](af-021-operations.md). До этого production-данных нет.
- Ответственный за восстановление — владелец проекта. RPO/RTO, место копий и порядок проверки восстановления фиксируются в #19 до появления реальных данных.
- Удаление реальных данных — после завершения эксперимента и подтверждения результатов. Точную дату и ответственного назначает владелец проекта.

## Расходы

- Платные внешние вызовы по умолчанию не выполняются; при включении LLM лимит задаётся `ACTIONFLOW_LLM_BUDGET_USD`.
- Платная инфраструктура (облачная БД, хостинг, управляемый Temporal) не разворачивается.
- Учитывать стоимость каждого запуска по спецификации, останавливать платные запуски при достижении лимита, неизвестную стоимость сохранять как неизвестную, а не как ноль.
- Владелец решения о провайдере и лимите — владелец проекта.

## LLM и embeddings

- Внешние LLM/embedding API разрешены. Текст синтетических fixtures может передаваться выбранному провайдеру; реальные клиентские данные требуют отдельного согласования.
- Для выбранной интеграции задаются `ACTIONFLOW_LLM_PROVIDER=vsellm`, `ACTIONFLOW_LLM_BASE_URL=https://api.vsellm.ru/v1`, `ACTIONFLOW_LLM_MODEL=openai/gpt-5.5` и `ACTIONFLOW_LLM_API_KEY` либо совместимые переменные `OPENAI_*`. Токен и лимит расходов хранятся в кабинете провайдера и локальном `.env`; ключ не записывается в репозиторий.
- Worker требует положительный `ACTIONFLOW_LLM_BUDGET_USD` для запуска внешнего адаптера. Эта настройка пока служит обязательным opt-in и не ограничивает накопленные расходы автоматически; фактический жёсткий предел задаётся на стороне VseLLM.
- Embeddings не обязательны для базового сценария и включаются только при настроенном провайдере.
- Конфигурация провайдера, модели, ключей, таймаута, повторов и бюджета задаётся в локальном `.env` (шаблон — `.env.example`); секреты не коммитятся.
- Если провайдер, модель или ключ не настроены, используется локальный детерминированный baseline `local-baseline-unanswered-v1` с `cost_usd = null`. Поддерживаются переопределения `ACTIONFLOW_LLM_PROVIDER`, `ACTIONFLOW_LLM_MODEL`, `ACTIONFLOW_LLM_API_KEY` и `ACTIONFLOW_LLM_BASE_URL`.
- Неизвестная стоимость сохраняется как `null`, а не `0`; при известных тарифах используются `ACTIONFLOW_LLM_INPUT_COST_USD_PER_MILLION` и `ACTIONFLOW_LLM_OUTPUT_COST_USD_PER_MILLION`.

## Последствия

- #4 разблокирован для выбора версий и окружения; конкретный LLM-провайдер по умолчанию не выбран.
- Задачи M1 могут использовать внешний адаптер после заполнения `.env`; без него остаётся локальный baseline.
- #19 уточнил резервное копирование и восстановление до появления реальных данных.
- Решение пересматривается при появлении реальных данных, живого пилота или изменении бюджета.
