# AF-023, часть 1. Сравнение локальных конфигураций и выбор кандидата

Дата: 2026-11-23. Задача: [#22](https://github.com/alkselsv/ActionFlow/issues/22). Протокол: [AF-025](af-025-evaluation-protocol.md). Правила и разметка: [AF-002](af-002-annotation.md), редакция от 2026-11-21.

**Выбор по качеству на development: `local-baseline-unanswered-v1`, правила `local-unanswered-v3`, prompt/rules `unanswered-rules-v3`; commitment и complaint остаются на `local-commitment-v1` и `local-complaint-v1`.** Это лучший из сравнённых локальных кандидатов, но пока не рекомендация к независимой проверке: AF-025 требует пройти стоимостной порог, а фактическая вычислительная стоимость неизвестна (`cost_usd: null`). До её измерения или отдельного решения менеджера кандидат не проходит этот gate. Сравнение использует три реальные версии локального детектора из истории Git и изменяет только правила unanswered. Внешние LLM-кандидаты не запускались: локальный `.env` и переменные процесса не содержат provider, model, API key или бюджет.

## Что проверено

Воспроизведён AF-020 на 7 срезах разработки (5 чатов, 30 сообщений, 10 ожидаемых карточек). Сравнивались кандидаты `local-rules-v1`, `local-rules-v2` и `local-rules-v3`; model ID и все остальные части конфигурации одинаковы. Отложенная часть вообще не запускалась. Повторный прогон подтвердил совпадение SHA-256 детерминированных результатов по каждому кандидату.

Это локальные измерения на текущей машине, не оценка эксплуатационного p95. Внешние расходы равны $0; фактическая вычислительная стоимость не измерена, поэтому `cost_usd` остаётся `null`. Согласно AF-025 §5 и §7.2 неизвестная стоимость не считается пройденным порогом без отдельного решения менеджера. Следовательно, результат этой задачи — сравнительный выбор кандидата по качеству; допуск к независимой проверке остаётся заблокированным до оценки стоимости или решения менеджера.

Локальные правила не вызывают внешний prompt/API. Воспроизводимость обеспечивают source commits и SHA-256 набора, challenges, разметки, evaluator и `uv.lock` в JSON-артефакте. Команда из корня репозитория запускает все три версии дважды, фильтрует только development-срезы и записывает итоговый JSON:

```powershell
uv run --project backend --frozen python experiments/af023_model_comparison/run_comparison.py
```

## Ошибки и ограничения

- Все кандидаты равны на существующей разработке: 10 / 0 / 0 суммарно по трём типам. Дискриминирующий результат дают 5 дополнительных synthetic development challenges, созданных для известных классов ошибок. Их метки составил агент по AF-002 и сценарию M1; менеджер их отдельно не проверял. Они помогают выбрать версию правил для следующей проверки, но не считаются независимой оценкой качества.
- Challenge `c-102` — конкретный ответ «Покажем завтра в 11:00» на вопрос о времени: v1 ошибочно оставляет unanswered, v2/v3 закрывают. Challenge `c-101` — сообщение о прекращении приёма платежей без вопросительного знака: v1/v2 пропускают, v3 создаёт карточку. Подтверждение без решения (`c-103`) остаётся открытым у всех версий; нейтральное сообщение и содержательный ответ (`c-104`, `c-105`) не создают карточек.
- В M1 пропуск обязательства в `n-007` был связан с промежуточными состояниями обязательства, которые считались отдельными карточками. Правило и подсчёт итогового состояния исправлены; текущий прогон разработки пропусков не показывает. Этот пример уже участвовал в исправлении и не является независимым свидетельством.
- В `s-001` ответ сотрудника «Покажем завтра в 11:00» ранее оставлял ложную карточку обращения. После исправления AF-022 повторный прогон не показывает лишнюю карточку. `s-001` исключён из разработки и уже загрязнил первоначальную отложенную часть; он не доказывает независимое качество.
- Правила M1 различают перенос, отмену и исполнение обязательства, но малая синтетическая выборка не доказывает их полноту. Для переноса вывод зависит от истории сообщений, доступной в конкретном срезе.
- В сравнении все кандидаты используют один и тот же `local-commitment-v1`; переносы и отмены поэтому не разделяют версии unanswered и не дают основания ранжировать их. M1 сценарии подтверждают поведение этого общего commitment-детектора, а новые варианты переноса/отмены должны войти в независимый набор.
- История срезов ограничена экспортом; отсутствие наблюдения не доказывает отсутствие последующего события. В разработке не проверяется влияние неизвестной стороны и вложений на качество реальных экспортов.
- Одна локальная конфигурация с идеальными метриками на 10 карточках не сравнивает модели и не подтверждает прохождение порогов для решения о пилоте.

Цена конкретных ошибок для бизнеса не измерялась. Измеренные нулевые FP/FN/SLA ошибки относятся только к небольшому набору разработки; риск ошибки на реальных чатах остаётся неизвестным.

## Решение и следующий эксперимент

Зафиксировать v3 как лучшую по качеству базовую локальную конфигурацию в этом сравнении: она не хуже v1/v2 на существующей разработке, исправляет обе разницы на challenge-кейсах и даёт совпадающий детерминированный результат при повторе. Переход к независимой проверке пока заблокирован стоимостным gate AF-025: фактическая вычислительная стоимость остаётся `null`, отдельного решения менеджера нет. Даже после разрешения этого gate потребуются новая независимая выборка не менее 10 чатов, 30 сообщений и 5 карточек каждого типа; текущие данные этого условия не выполняют. Сравнительных данных по переносу и отмене обещаний между кандидатами нет, поскольку commitment-детектор оставался неизменным. Это не вывод о внешних LLM и не допуск к пилоту.

Чтобы завершить сравнение по #22:

1. Сначала измерить локальную вычислительную стоимость v3 либо получить отдельное решение менеджера по `cost_usd: null`. Только после прохождения этого gate готовить замороженный независимый набор по AF-025 и выполнять проверку; не переносить synthetic challenge labels в независимую часть.
2. Если владелец позже настроит provider, model, key и бюджет в локальном `.env`, добавить внешние модели новым сравнением на development-срезах; ключ не передавать в GitHub, чат или репозиторий. Внешние расходы M2 ограничены $10 суммарно и $0.10 за анализ.
3. Решение о пилоте оставить отдельным для AF-025: учитывать независимые результаты, полноту данных и фактическую стоимость.
