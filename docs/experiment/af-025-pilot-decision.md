# AF-025, часть 3. Решение по ограниченному живому пилоту

Дата: 2026-11-23. Issue: [#26](https://github.com/alkselsv/ActionFlow/issues/26). Основание: [протокол AF-025](af-025-evaluation-protocol.md) и [диагностическая оценка #25](af-025-independent-evaluation.md).

## Вердикт

**Не допускать конфигурацию `local-baseline-unanswered-v1` / `local-unanswered-v3` к живому пилоту. Решение: исправить и повторно оценить.** Решение принято по версии конфигурации, проверенной в #25, а не по продукту в целом.

## Проверка условий

| Условие AF-025 | Результат | Решение |
| --- | --- | --- |
| `unanswered`: precision ≥ 80%, recall ≥ 90% | 25%, 100% на synthetic labels | Не пройдено: precision |
| `commitment`: precision ≥ 80%, recall ≥ 90% | 33,3%, 100% на synthetic labels | Не пройдено: precision |
| `complaint`: precision ≥ 80%, recall ≥ 90% | 100%, 100% на synthetic labels | Пройдено только на диагностическом synthetic наборе |
| Валидность/полнота оснований | 15/15 совпавших карточек | Пройдено на synthetic labels; человеческой верификации нет |
| Критические пропуски / дубли | 0 / 0 | Пройдено только в этом ограниченном прогоне |
| SLA | 0 размеченных SLA-кейсов | Не оценено, условие не пройдено |
| Задержка | медиана 0,048 с; диапазон 0,035–0,210 с | Локальный диагностический замер, не эксплуатационный p95 |
| Стоимость | `cost_usd: null` | Не пройдено; неизвестность не считается нулём |
| Независимость/репрезентативность | набор и метки сгенерированы агентом | Не подтверждена для реального использования |
| Cognee | по #23 «требует исправления», по #24 отложен | Исключён; выбранный baseline использует прямой контекст |

Средние значения по типам не компенсируют провал precision или непроверенные SLA/стоимость. Синтетическая оценка не подтверждает качество на клиентских переписках.

## Границы пилота

Живой пилот **не запускается**. В рамках этого решения не подключаются клиентские чаты, бот не получает клиентский поток, анализ реальных сообщений не включается. Границы пилота сейчас нулевые; нет оператора живого мониторинга, поскольку пилот не разрешён. Перед новым решением менеджер должен назначить ответственного.

Если в будущем пилот будет одобрен, его остановка обязательна при любом критическом пропуске, невалидном/неполном основании, ошибке SLA, дубле, утечке между проектами, позднем факте, нарушении лимита стоимости/задержки или нарушении политики данных. Полнота приёма/восстановления бота должна быть проверена отдельно в M3.

## Исправления и повторная оценка

1. Разобрать FP `unanswered` и `commitment` на разрешённой разработке #22; не подстраивать правила под уже просмотренный synthetic набор #25.
2. Зафиксировать исправленную конфигурацию новым commit и повторить разработочную оценку, включая SLA-кейсы.
3. Создать новую независимую выборку, не переиспользуя v2 как независимую после просмотра результатов; разметку должен проверить доменный эксперт. Синтетические метки остаются только диагностикой.
4. Измерить локальную стоимость или получить отдельное явное решение менеджера; `null` gate не пройден.
5. Провести новую независимую оценку по неизменному протоколу и только затем повторно рассмотреть #26.

Это закрывает текущую часть решения #26 отрицательным вердиктом. Переход к M3 и живому клиентскому пилоту не разрешён.
