# AF-001: исходные данные первого эксперимента

Дата: 2026-11-20. Статус: согласовано владельцем продукта в [issue #1](https://github.com/alkselsv/ActionFlow/issues/1). Связанные документы: [спецификация](../specs/responseflow-mvp.md), [дорожная карта](../ROADMAP.md), [описание fixtures](../../data/fixtures/telegram/README.md).

## Решение

Реальных клиентских чатов Vedita для первого эксперимента нет, и они не будут предоставлены. Источник данных эксперимента — синтетический Telegram-style набор в `data/fixtures/telegram/`: 9 чатов, 43 сообщения, 14–15 сентября 2026 года, только текст.

Набор синтетический, поэтому он хранится и публикуется в Git без обезличивания. Требование «реальный экспорт — вне Git» сохраняется для любых реальных данных, если они появятся позже. Реальный экспорт Telegram не проверялся и не требуется для этого этапа.

## Обработка и публикация

Разрешено:

- использовать набор для разработки, импорта, разметки и автоматических проверок;
- публиковать fixtures в репозитории и GitHub Issues: данные синтетические;
- добавлять новые синтетические примеры с явной пометкой `_actionflow_fixture.synthetic`.

Запрещено:

- добавлять в Git реальные переписки, экспорт, вложения, документы, секреты и учётные данные;
- выдавать синтетические примеры за реальные данные Vedita или за подтверждение фактического формата Telegram;
- публиковать реальные имена, компании, контакты, ссылки, номера договоров и заказов.

Если реальные данные появятся позже:

- хранить их вне Git, в согласованной локальной папке `C:\Users\79622\ActionFlowData\<AF-ID>\` (путь уточняется перед использованием);
- обрабатывать только с разрешения владельца данных и только в согласованном контуре;
- перед добавлением в репозиторий обезличивать: заменять имена и названия компаний, телефоны, e-mail, ссылки, адреса, номера договоров, заказов и счетов, суммы; сохранять порядок сообщений, ID и связи ответов;
- не восстанавливать и не выдумывать отсутствующие редакции, удаления и вложения.

Техническая защита: `.gitignore` исключает всё содержимое `data/`, кроме `data/fixtures/`.

## Объём и ограничения

- 9 чатов, 43 сообщения, период 2 дня, один ответственный менеджер.
- Ориентир 10–30 чатов не достигнут и не является обязательным минимумом. Набор меньше ориентира — это ограничение эксперимента.
- Только текст. Нет вложений, голосовых, фото, файлов, пересланных сообщений, составных текстовых полей (`text` всегда строка), системных событий Telegram, редакций и удалений (`revision` всегда 1), повторной загрузки и неизвестного участника.
- `date` хранит UTC, тогда как реальный экспорт Telegram использует локальное время чата. Импортёр не должен предполагать, что fixtures воспроизводят реальную схему.
- Исходный нормализованный JSONL, из которого собраны fixtures, в репозитории отсутствует. Единственная сохранённая форма набора — сами fixtures; преобразование из источника не воспроизводится.
- Качество на синтетическом наборе — предварительное. Оно проверяет механику и сохранение оснований, но не переносится автоматически на реальные переписки Vedita. Для порогов M2 нужен отдельный согласованный набор или явное решение о работе только на синтетике.

## Проверка

Команда:

```text
python scripts/validate_fixtures.py
```

Проверяются: UTF-8 без BOM, разбор JSON, пометка синтетического набора, уникальность `id` и `external_id`, порядок сообщений, наличие обязательных полей, согласованность `date`/`date_unixtime`/`sent_at`, `observed_at` не раньше `sent_at`, разрешимость ссылок ответов, допустимые роли, отсутствие контактных данных и уникальность пар `workspace_id`/`conversation_id`.

- [#3](https://github.com/alkselsv/ActionFlow/issues/3) работает с этим набором и фиксирует принятые допущения о формате; проверить фактическую схему реального Telegram export он не может.
